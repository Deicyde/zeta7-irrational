## Existing Lean

Branch `formalize/outer-estimate` (commit `0f0a541`, module
`ZetaSeven.OuterEstimate`, not on main) already defines most of this
node: `OuterRange` (52), `rankCorr` (54), `outerWeightDbl` (twice (56),
the doubled convention of `ZetaSeven.rank_lemma`), `classV`, `classU`,
`classT` (58), and `gammaOut` (59). Reuse them. `removedCost` and
`unremovedCost` encode the paper's (57); the class-basis route does not
use them, and this node does not own (57).

Warning: that `gammaOut` (`ZetaSeven/OuterEstimate.lean`, line 97 at
`0f0a541`) has only the two clauses of (59) and no `p > K` case. For
`p > K` it falls into the `K < 2p` clause and returns a nonzero value,
where this node and Section 5.1 put `γ^out_p = 0`. Add the case (for
example `if K n < p then 0 else ...`) before the normalization (60) or
the outer limiting functions use it; the outer estimate itself only
needs the two clauses under (52).

Not there yet: the indicator `δ_a`. The zero-class weights moved to
the outer weight family node on 2026-10-18.

The half-range `m` and the class count `ℓ_A(a)` belong to the local
range data node: `ZetaSeven.mHalf` and `ZetaSeven.ell`
(`ZetaSeven/InnerEstimate.lean`, on main since round 5, with
`ell p A a` defined for every `a`). Use those, not a new copy, when
rebasing the branch module.
